## 4. 启动链路

```
QQChatbot.exe
   │
   ├─ 1. 解析 BASE = Path(exe).parent          ← 绝不用 cwd
   ├─ 2. 路径体检（长度 / 可写 / 磁盘）
   ├─ 3. 单实例锁 data/.instance.lock
   │      └─ 已持有 → 唤起已有窗口，本进程退出
   ├─ 4. 加载 config/instance.yaml
   ├─ 5. 解密 config/secrets.dat
   │      └─ 失败 → 进入配置向导模式
   ├─ 6. 打开/迁移 data/bot.db
   ├─ 7. 启动 Uvicorn 于 127.0.0.1:0（系统分配端口）
   ├─ 8. 写 runtime/url.txt，启动 pywebview 窗口
   └─ 9. 后台启动 WS 接入（若已配置）
```

任何一步失败：
- 1–6 失败 → 弹出可读错误窗（不静默退出）
- 7–8 失败 → 降级为默认浏览器打开
- 9 失败 → 窗口正常可用，托盘变黄，界面显示重连中

## 5. 路径规则（硬约束）

### 5.1 长度（动态预算，不写死）

本机 `LongPathsEnabled = 0`，MAX_PATH = 260。BASE 能有多长，取决于打包产物里**最深的那个文件**。

所以不要硬编码一个数字，而是构建时扫描并落盘：

```json
// app/path-budget.json
{ "max_rel_len": 67, "checked_at": "2026-10-29" }
```

运行时：

```
allowed = 260 - max_rel_len - 10
if len(BASE) > allowed: 拒绝启动并提示"请将程序移动到更短的路径"
```

| 项 | 值 |
|---|---|
| 实测 `max_rel_len`（空壳产物） | 67 |
| 对应 `allowed` | **183** |
| manifest 缺失时兜底 | 150 |
| 安全余量 | 10 字符 |

实测结论：**191 字符的 BASE 仍然能正常启动**，所以当初拍的 120 过于保守。改成动态预算后，既不会误伤，也不会漏判。

**不要用 `\\?\` 前缀绕过。** SQLite、日志轮转、子进程参数对它的支持不一致，代价大于收益。宁可让用户挪目录。

### 5.2 推导

| 禁止 | 正确 |
|---|---|
| `os.getcwd()` | `Path(sys.executable).parent`（打包后） |
| `Path(__file__)`（打包后不可靠） | `Path(sys._MEIPASS)` 仅用于 `_internal` 内资源 |
| 用户目录 / AppData / 注册表 | 全部相对 BASE |

### 5.3 临时文件

**不放 `%TEMP%`。** 全部放 `runtime/tmp/`，退出时清理。

原因：`%TEMP%` 可能被清理工具删除、可能在不同会话下路径不同、且会让"删文件夹=卸载"失效。

### 5.4 编码

- 所有文本文件 UTF-8（无 BOM）
- 日志、配置、数据库路径一律显式 `encoding="utf-8"`
- 中文路径已实测可写，但**必须纳入回归测试**

## 7. 单实例与端口

| 项 | 规则 |
|---|---|
| 互斥 | `data/.instance.lock` 文件锁，进程退出由 OS 释放 |
| 重复启动 | **不报错**，唤起已运行实例的窗口后自身退出 |
| 端口 | `127.0.0.1:0`，由系统分配，**不固定** |
| 端口记录 | 写入 `runtime/url.txt`，含一次性访问令牌 |
| 多实例 | 不同文件夹 = 不同实例 = 不同端口，天然不冲突 |
| 同 appId 检测 | L2 临时锁 `%TEMP%/qqbot-<hash>.lock`（见架构 D7） |

## 8. 自检（doctor）

**这是"确认能跑"的可执行形式。** 首次启动自动运行一次，之后可在托盘手动触发。

### 8.1 检查项

| # | 检查 | 失败后果 |
|---|---|---|
| D01 | BASE 长度 ≤ `260 − max_rel_len − 10` | 拒绝启动 |
| D02 | BASE 所在磁盘可写 | 拒绝启动 |
| D03 | 剩余空间 ≥ 500 MB | 警告 |
| D04 | 创建/删除含中文与空格的文件 | 拒绝启动 |
| D05 | SQLite 打开 + WAL 写入 + 中文路径 | 拒绝启动 |
| D06 | 文件锁可获得 | 走"已运行"分支 |
| D07 | 可绑定 `127.0.0.1:0` | 降级到浏览器模式 |
| D08 | WebView2 可用 | 降级到浏览器模式 |
| D09 | 系统时间与网络时间偏差 ≤ 5 分钟 | 警告（影响签名/时效） |
| D10 | 可解析并 TLS 连接 `api.bot.qq.com` | 警告（离线模式） |
| D11 | `runtime/tmp` 可写 | 拒绝启动 |
| D12 | 日志目录可写且可轮转 | 拒绝启动 |

### 8.2 输出

同时产出两份：

- **人读**：窗口内列表，绿/黄/红三色，红色项附一句修复建议
- **机读**：`runtime/doctor.json`

```json
{
  "ok": true,
  "base": "C:\\QQChatbot",
  "os": "10.0.22000",
  "arch": "x64",
  "checks": [
    { "id": "D01", "status": "pass", "detail": "len=15" },
    { "id": "D04", "status": "pass", "detail": "中文+空格 OK" }
  ]
}
```

### 8.3 退出码

| 码 | 含义 |
|---|---|
| 0 | 全部通过 |
| 1 | 有警告但可运行 |
| 2 | 致命项失败，拒绝启动 |

## 9. 迁移验证清单

从机器 A 拷到机器 B，按顺序执行，全部通过才算迁移成功。

| 步 | 操作 | 预期 |
|---|---|---|
| 1 | 整文件夹拷贝（含 `data/`） | 文件数、大小一致 |
| 2 | 双击 `QQChatbot.exe` | 正常启动，不报缺少 DLL |
| 3 | doctor 自动运行 | 无红色项 |
| 4 | 打开配置 | **提示"密钥无法解密，请重新输入"** |
| 5 | 重填 appSecret / 模型 Key | 保存成功 |
| 6 | 查看群列表 | 群、角色卡、日志、会话**全部还在** |
| 7 | 连接状态 | 变绿，收到心跳 |
| 8 | 群里 @ 一次 | 正常回复 |
| 9 | 关闭窗口 | 进程仍在，托盘可见 |
| 10 | 再次双击 exe | 唤起已开窗口，不起第二个进程 |

### 9.1 预期内的"迁移失败"

| 现象 | 是否正常 |
|---|---|
| 密钥需重填 | ✅ 设计如此（DPAPI 机器绑定） |
| 需要确认 owner | ⚠️ 仅当 appId 变更时 |
| 端口变化 | ✅ 正常，URL 会重新生成 |
| 首次启动慢 5–15 秒 | ✅ Defender 扫描 |

### 9.2 不允许出现的现象

| 现象 | 说明 |
|---|---|
| 提示找不到 `python3xx.dll` | 打包不完整 |
| 中文路径报错 | 编码问题 |
| 数据丢失 | 数据库路径写成了绝对路径 |
| 静默退出无提示 | 启动异常未捕获 |
| 需要装 Python / VC++ | 依赖没打进去 |

## 10. 构建环境前置条件

**构建机 ≠ 运行机。** 产物自带运行时，但打一次包需要：

| 项 | 要求 |
|---|---|
| Python | **3.15.2 x64（本机已装）** |
| 版本策略 | 3.13+ 均可；3.15.2 已实测通过 |
| 打包工具 | PyInstaller，`--onedir`，**不用 `--onefile`** |
| 构建产物 | 整个 `dist/QQChatbot/` 文件夹 |

若换新机器构建：

```powershell
winget install -e --id Python.Python.3.15
```

> 为什么不用 `--onefile`：每次启动要解压到临时目录，慢 3–10 秒，且极易被杀软误报。

## 11. 已知风险与缓解

| # | 风险 | 概率 | 缓解 |
|---|---|---|---|
| R1 | Defender 对 PyInstaller 产物误报 | 中 | onedir + 首次运行引导 + 可选代码签名 |
| R2 | 用户放到超长路径 | 中 | D01 启动即拦截 |
| R3 | 目标机无 WebView2 | 低 | 降级浏览器模式，不阻断 |
| R4 | 目标机是 ARM64 | 低 | 首版不支持，启动时检测并提示 |
| R5 | 休眠/待机后 WS 断开 | 高 | 自动重连 + 托盘状态提示 |
| R6 | 用户从 U 盘/网络盘运行 | 中 | 检测到网络路径时警告（SQLite 锁不可靠） |
| R7 | 中文杀软路径拦截 | 低 | 日志明确记录失败路径 |
| R8 | 系统时间偏差导致 API 失败 | 低 | D09 检查并提示 |

### 13.5 构建期实际踩坑

| 问题 | 现象 | 解决 |
|---|---|---|
| **PyYAML 无 cp315 wheel** | `pip install pyyaml` 触发源码编译，失败 | 改用纯 Python 的 **`ruamel.yaml`**，无编译依赖，打包更稳 |
| **PowerShell 5.1 + UTF-8 无 BOM** | 含中文的 `.ps1` 报「表达式或语句中包含意外的标记」 | 构建脚本一律 **ASCII-only** |
| **`--noconsole` 下 `sys.stderr` 为 None** | 日志 StreamHandler 抛异常 | 仅当 stderr 存在才挂控制台 handler |
| 中文路径下创建 venv / 打包 | 正常 | 无需特殊处理，但保留回归测试 |

> 这三条都会在"换一台机器重新构建"时复现，所以写进规格。
