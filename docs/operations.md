# 部署与运维

## 一、初始启动

1. 把整个 `QQChatbot` 文件夹放到较短路径，例如 `D:\QQBot`
2. 双击 `QQChatbot.exe`
3. 在「基础设置」填写 AppID / AppSecret
4. 选择模型服务，填写 Base URL、模型名和 API Key
5. 到 QQ 开放平台配置 IP 白名单
6. 把机器人拉进群，在「群聊与黑名单」批准该群

程序只监听 `127.0.0.1`，管理界面不会暴露到局域网。

## 二、目录

```
QQChatbot.exe
app\            程序本体和 path-budget
config\         instance.yaml + secrets.dat
data\           bot.db
logs\           qqbot.log
runtime\        url.txt、临时文件、诊断包
profiles\       人设包
plugins\        规则 / 游戏 / 模式 / 代码插件
```

- `config\secrets.dat` 由 Windows DPAPI 加密，与本机当前用户绑定
- 复制整个文件夹到另一台机器，必须重新填写密钥
- `runtime\` 可以随时删除

## 三、升级

### 从旧版本升级（保留数据）

1. 关闭旧程序
2. 旧版先做一次「数据备份 → 下载备份」（建议）
3. 把新版 zip 解压到一个新目录，例如 `D:\QQBot2`
4. 从旧目录复制这些到新目录：
   - `data\bot.db`
   - `config\instance.yaml`
   - `config\secrets.dat`（同一台电脑、同一个 Windows 用户才有效）
   - `profiles\`（如果改过人设包）
   - `plugins\` 下自己写的规则 / 游戏 / 模式 / 代码插件
5. 启动新版，数据库会自动补齐新增的表和列

- 同一台电脑同一用户：`secrets.dat` 可以直接用
- 换机器：`secrets.dat` 必须重新填写 AppSecret 和模型 Key
- 不要用旧 `plugins\` 整个覆盖新版：新版自带的规则和游戏会被旧文件覆盖，
  旧版遗留的 `lucky.py` 也会被带回来
- 不要同时运行新旧两个实例，同一个 AppID 会重复收消息

### 开发机升级

1. 关闭 `QQChatbot.exe`
2. 运行 `.\build.ps1`
3. 脚本会保留 `config`、`data`、`logs`、`runtime`、`profiles`、`plugins`
4. 内置规则包会覆盖同名文件；自己写的规则/游戏/代码插件不会被覆盖

打包脚本保持 ASCII-only，路径预算由构建产物自动计算。

## 四、备份

「基础设置 → 数据备份 → 下载备份」：

zip 内包含：

```
data/bot.db
profiles/...
plugins/...
manifest.json
```

不包含：

- `config/secrets.dat`
- AppSecret
- 模型 API Key
- `config/instance.yaml`

备份前会执行 SQLite WAL checkpoint，保证数据库文件完整。

## 五、恢复

「基础设置 → 数据备份 → 恢复备份」选择 zip。

- 校验路径：拒绝绝对路径、`..`、`secrets.dat`、未知顶层目录
- 使用 SQLite 在线备份回写当前数据库，不需要关闭程序
- 恢复 `profiles/` 与 `plugins/`
- 恢复后建议重启程序，确保插件和配置完全刷新

恢复不会覆盖账号配置和密钥。

## 六、清空业务数据

「基础设置 → 数据备份 → 清空业务数据」，输入 `RESET` 确认。

清空：

- 群、角色卡、记忆
- 审计、频率、额度
- 规则 / 游戏 / 插件启用状态
- 待发送的模式说明
- 日志

保留：

- AppID / AppSecret
- 模型 Key
- `config/instance.yaml`
- `plugins/` 文件
- `profiles/` 文件

## 七、日志与诊断

- 日志自动脱敏，不写 access_token、rkey、AppSecret、完整 openid
- 「清空日志」会截断正在写入的 `qqbot.log`，并删除轮转文件
- 「导出诊断包」包含配置摘要、日志、路径信息，不包含密钥

### 审计记录

- 审计存在 `audit` 表，记录群审批、规则切换、插件错误、失败的 wiki 查询等
- 默认保留 30 天，每小时自动清理一次，另外硬上限 5000 条
- 「日志 → 清理审计记录」可以手动清理：输入天数保留，输入 0 全部清空
- 保留天数在「回复设置 → 运行参数」里改，0 表示不按时间清理，只保留最近 5000 条
- wiki 查询成功不写审计，只有失败和关键词翻译（含 token 数）会记一条

## 八、每日刷新

每日类小游戏和 Boss 使用本地自然日：

- 状态里保存 `__date`
- 下次指令发现日期变化时自动清空当天状态
- 断线跨越一天也会在下次指令时刷新
- 长期统计放在 `stats`，不会随日期清空

## 九、群聊监听与主动消息

- 监听需要群主在手机 QQ 的机器人设置里把「机器人可获取的群聊消息范围」
  改成「获取群内全部消息」，否则平台不会推送普通群消息
- 回复时不 @ 用户会改用主动消息，需要群主开启群里的「机器人主动发言」；
  没有权限时程序会自动退回被动回复
- 主动消息有平台频控：单群每天最多 1000 条、每分钟最多 20 条
- 监听只在聊天模式生效，接话同样消耗模型额度和每日消息数
- 每个群要在「群聊与黑名单」里单独打开监听，并在旁边手填群人数
- 人数下限大于 0 时，没填人数或人数低于下限的群不会接话

## 十、安全要点

- 管理界面只绑定本机回环地址
- 密钥按服务分别保存，DPAPI 加密
- 日志统一脱敏
- 代码插件、规则 hook、游戏逻辑在子进程沙箱中运行
- 沙箱会拦截常见网络、写文件、子进程、ctypes 操作，但不是内核级隔离
- 只运行自己写的或可信来源的 `.py`
- `/wiki` 只会访问「模式与插件 → 内置插件」里明确列出的 https 站点，
  不跟随跨站跳转，解析到内网地址的请求会被拒绝；摘要缓存 12 小时

## 十、备份恢复的限制

- 不恢复账号配置和密钥
- 恢复旧版本备份时，数据库会自动补齐新表/新列
- 旧规则 id 会自动迁移：`coc7e → coc7th`、`paranoia25 → paranoia25th`
- 恢复后旧插件文件可能与当前内置插件并存，加载器会跳过已改名的旧 id
