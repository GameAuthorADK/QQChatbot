# 规则包检定规格（Check Spec）

> 本文只覆盖「检定」部分，不含角色创建、战斗、装备。
> 来源：`妄想症2E.pdf`（玩家手册部分，31 页）、`妄想症25周年版.pdf`（完整，205 页）。
> COC 7e 部分为通用认知，非本次 PDF 提取。

---

## 1. COC 7e（对照基线）

| 项 | 规则 |
|---|---|
| 骰型 | d100 |
| 判定 | 掷低，`roll ≤ 技能值` 成功 |
| 修正 | 奖励骰 / 惩罚骰（额外十位骰，取有利/不利值） |
| 大成功 | `01` |
| 极难成功 | `roll ≤ 技能/5` |
| 困难成功 | `roll ≤ 技能/2` |
| 普通成功 | `roll ≤ 技能` |
| 失败 | `roll > 技能` |
| 大失败 | 技能 < 50 时 `96–100`；技能 ≥ 50 时 `100` |
| 对抗 | 双方各掷，比较成功等级，高者胜；等级相同比技能值；**对抗骰不可推** |
| 推骰（Pushed） | 失敗后可重试一次，需给出合理解释；再失败后果更严重；Luck / SAN / 战斗 / 伤害 / 对抗骰不可推 |
| 难度等级 | 常规（≤技能）/ 困难（≤技能÷2）/ 极难（≤技能÷5） |
| 对抗 NPC 技能 | 对方技能 < 50 时需常规成功；> 50 需困难成功；≥ 90 需极难成功 |
| 目标是否公开 | 公开 |

> 来源：Chaosium Quick-Start 与官方 wiki。奖励骰/惩罚骰**互相抵消**后取净值，最多各 2 颗。

## 2. 妄想症 2E

| 项 | 规则 |
|---|---|
| 骰型 | d20 |
| 判定 | 掷低，`roll ≤ 目标值` 成功 |
| 目标值来源 | 技能优先；无对应技能时才用属性 |
| 技能范围 | 1–20 |
| 属性 | 8 项，各 1–20 |
| 大成功 | `1`，**即使技能值为 0** |
| 大失败 | `20`，**即使技能值为 20** |
| GM 修正 | 骰前增/减目标值，**可对玩家保密** |
| 对抗检定 | 无 |
| 成功等级 | 无，只有成功 / 失败 |

**技能基值查表**

| 属性值 | 技能基值 |
|---|---|
| 1–3 | 0 |
| 4–6 | 1 |
| 7–10 | 2 |
| 11–14 | 3 |
| 15–17 | 4 |
| 18+ | 5 |

**技能上限**：初始 12；本部门特殊训练可到 13 / 14。

**派生值**

| 派生 | 规则 |
|---|---|
| 载重量 | 力量 ≤ 12 → 25；> 12 时每点 +5 |
| 伤害加值 | 力量 1–13 → 0；14–18 → 1；19–20 → 2 |
| 英雄气概（减伤） | 同伤害加值，改用耐久 |

## 3. 妄想症 25 周年

### 3.1 五种检定形态

| 形态 | 规则 |
|---|---|
| 普通技能检定 | `1d20 ≤ 技能值` |
| 对抗检定 | 双方各掷，**比较差值（目标 − 骰值）**，大者胜；平手无人胜；双方失败无人胜 |
| 自由对抗 | 多人各掷，按差值降序排序，最高者获最大胜利；也可用于行动顺序 |
| 长期技能检定 | 多次检定累计成功次数；开放型（先达 N 次）或固定型（M 次内达 N 次） |
| 独断裁决（AJ） | `1d20 ≤ 10` → 是；`≥ 11` → 否 |

### 3.2 结果规则

> 本节仅供参考。妄想症为裸骰模式，引擎**不实现**任何判定。

| 项 | 规则 |
|---|---|
| 骰型 | d20 |
| 判定 | 掷低 |
| 大成功 | `1` |
| 大失败 | `20` |
| 差值 | `目标值 − 骰值`，越大越好 |
| 成功等级 | 无分级，仅成功 / 失败 + 差值 |

> 脚注：25 周年英文原文写作"a roll of 20, though not an automatic failure, means something bad happens"（即使成功也附带副作用）。实操中普遍按「1 大成功 / 20 大失败」处理，本方案采用桌规默认。因妄想症为裸骰模式，该判定权归 KP，引擎不实现。

### 3.3 目标值来源

| 来源 | 算法 |
|---|---|
| 技能 | `ceil(1d20 / 2)`，**最低 4** |
| 专精 | 技能 + 4（上限 18）；使用时**替代**统合技能等级 |
| 能力点 | `max(1d20, 8)` |
| 门路点 | `ceil(1d20 / 4)` → 1–5 |
| AJ | 固定 10 |

### 3.4 六项技能

处世（Management）、隐秘（Stealth）、武力（Violence）、硬件（Hardware）、软件（Software）、湿件（Wetware）。

> **术语修正**：Chutzpah、Moxie、Bootlicking、Intimidation 等是 **Management 下的专精**，不是技能名。此前把它们误列为技能。

### 3.5 搞事点数（Perversity Points）

| 项 | 规则 |
|---|---|
| 效果 | 每花 1 点，目标成功值 **±1** |
| 上下限 | **无**，可 > 20 或 < 1 |
| 默认花费上限 | 每次检定 ≤ 5 点，每人一次机会 |
| 可放开 | GM 可改为无限拍卖式花费 |
| **可秘密花费** | 是 |
| **可代他人花费** | 是 |

> **本规则不进入引擎**。理由见 §9：妄想症的判定权归 KP，引擎只负责掷骰。

### 3.6 紧张等级（Tension）

GM 私下维护 0–20 的紧张等级，表示一次行动被目击的概率阈值。**属于隐藏信息，不应由 bot 公开。**

## 4. D&D 5e

> 来源：SRD 5.1（5thsrd.org），与 PHB 规则一致。

### 4.1 检定结构

```
d20 + 属性调整值 + 熟练加值（若熟练） ≥ DC  → 成功
```

**与前三套方向相反：d20 掷高，不是掷低。** 这是抽象层必须支持 `compare: gte` 的直接原因。

| 组成 | 说明 |
|---|---|
| 属性调整值 | `floor((属性值 − 10) / 2)` |
| 熟练加值 | 随等级变化，+2 ~ +6 |
| DC | 由 GM 设定 |

### 4.2 DC 参考

| 难度 | DC |
|---|---|
| 极易 | 5 |
| 简单 | 10 |
| 中等 | 15 |
| 困难 | 20 |
| 极难 | 25 |
| 几乎不可能 | 30 |

### 4.3 优势 / 劣势

| 情况 | 规则 |
|---|---|
| 优势 | 投 2d20，取**高** |
| 劣势 | 投 2d20，取**低** |
| 多个优势叠加 | **不叠加**，最多只多投一颗 |
| 同时有优势和劣势 | **全部抵消**，只投 1d20 |

注意与 COC 的区别：COC 的奖励骰是**额外一颗十位骰**，5e 是**额外一颗完整 d20**。两者都叫"多投一颗"，但语义完全不同。

### 4.4 自然 1 / 20

| 场景 | 1 | 20 |
|---|---|---|
| 攻击检定 | 必定未命中 | 必定命中（重击） |
| 死亡豁免 | 计 2 次失败 | 恢复 1 HP |
| **属性检定** | **无特殊效果** | **无特殊效果** |
| **豁免检定** | **无特殊效果** | **无特殊效果** |

**这是最容易做错的一条。** 很多 bot 会把"20 = 大成功 / 1 = 大失败"套到所有检定上，5e RAW 不支持——只有攻击检定和死亡豁免有自然 1/20 规则。

对比：COC 和妄想症都是**全检定**都有 1/20 特例，5e 恰恰相反。

### 4.5 对抗检定（Contest）

双方各投 `d20 + 修正`，**比较总值**，高者胜。

- 平手：局面维持原状（**不重投**）
- 没有"双方都失败"的概念——因为不是对 DC

三种对抗的比较方式各不相同：

| 规则 | 比较对象 |
|---|---|
| COC 7e | **成功等级**（大成功 > 极难 > 困难 > 普通） |
| DND 5e | **总值**（含所有修正） |
| 妄想症 25 周年 | **差值**（目标 − 骰值） |

### 4.6 被动检定

```
10 + 全部修正
```
有优势 +5，有劣势 −5。不投骰。

### 4.7 豁免检定

`d20 + 属性调整值 +（若熟练）熟练加值 ≥ DC`。结构与属性检定相同，只是加值来源不同。

### 4.8 对角色卡的要求

DND 5e 是 `full` 判定模式，引擎必须能算出每次检定的加值：

| 需要 | 说明 |
|---|---|
| 6 项属性值 | 用于算调整值 |
| 等级 / 熟练加值 | 影响所有熟练项 |
| 18 项技能的熟练标记 | 布尔值 |
| 6 项豁免的熟练标记 | 布尔值 |
| 其他加值 | 专长、装备、状态 |

比重远大于妄想症，但这是 `full` 模式的必然代价。

## 5. 四套规则的差异矩阵

| 维度 | COC 7e | DND 5e | 妄想症 2E | 妄想症 25 周年 |
|---|---|---|---|---|
| 骰型 | d100 | d20 | d20 | d20 |
| 方向 | 掷低 | **掷高** | 掷低 | 掷低 |
| 目标来源 | 技能 / 属性 | **DC（固定）** | 技能 / 属性 | 技能 / 专精 / 属性 / 固定 |
| 加值 | 无 | **属性调整 + 熟练** | 无 | 无 |
| 结果分级 | 6 级 | 2 级 | 2 级 | 2 级 + 差值 |
| 自然 1 / 20 | 01 / 96–100 | **无特殊规则**（除攻击） | 1 / 20 | 1 / 20 |
| 修正 | 奖励骰（十位骰） | 优势（整颗 d20） | GM 秘密加减 | 搞事点数 |
| 对抗 | 比成功等级 | **比总值** | 无 | 比差值 |
| 长期检定 | 无 | 无 | 无 | 有 |
| 是/否裁决 | 无 | 无 | 无 | 有 |
| 目标是否公开 | 是 | 是 | **否** | **否** |
| 判定模式 | `full` | `full` | `roll-only` | `roll-only` |

**结论：不能把「检定」实现成一个固定的 d100 函数。** 它至少需要五个正交维度——骰型、方向、目标来源、加值、结果分级——外加"谁可以看见"。

特别地，**四套规则在"自然 1/20"上分成两类**：

| 规则 | 1 | 20 |
|---|---|---|
| COC 7e | `01` 大成功 | 大失败（阈值随技能变化） |
| 妄想症 2E | 大成功 | 大失败 |
| 妄想症 25 周年 | 大成功 | 大失败 |
| DND 5e | **无特殊效果** | **无特殊效果** |

三套 d20 掷低规则统一用 1/20；COC 用百分比阈值；DND 的属性检定与豁免检定根本没有这条规则。因此仍然**必须逐规则配置**，不能全局硬编码。

## 6. 抽象后的 Check DSL

### 6.1 结构

```yaml
check:
  id: coc7th_skill
  dice: "1d100"
  compare: lte                 # lte | gte
  target:
    source: skill              # skill | specialization | attribute | fixed | lookup
  margin: "target - roll"      # 可选，用于对抗与长期检定
  outcomes:                    # 按序匹配，命中即止
    - { when: "roll == 1",                    label: 大成功, rank: 5 }
    - { when: "roll <= floor(target/5)",      label: 极难成功, rank: 4 }
    - { when: "roll <= floor(target/2)",      label: 困难成功, rank: 3 }
    - { when: "roll <= target",               label: 成功,   rank: 2 }
    - { when: "roll >= 96",                   label: 大失败, rank: 0 }
    - { else: true,                           label: 失败,   rank: 1 }
  reveal: full                 # full | roll-only | hidden
```

```yaml
check:
  id: dnd5e_ability
  dice: "1d20"
  compare: gte                 # 掷高：总值 ≥ DC 才算成功
  target:
    source: fixed              # DC 由 GM 给出
  add: [ability_mod, proficiency_if_proficient]
  modifiers:
    - { id: advantage,    kind: keep_high, dice: "2d20", visible: true }
    - { id: disadvantage, kind: keep_low,  dice: "2d20", visible: true }
  outcomes:
    - { when: "total >= dc", label: 成功, rank: 1 }
    - { else: true,          label: 失败, rank: 0 }
  reveal: full
```

妄想症两版**没有 check 块**——裸骰模式不注册目标、不注册分级，只掷骰。

### 6.2 形态声明

| 形态 | 说明 | 适用 |
|---|---|---|
| `normal` | 对目标值判定 | 全部 |
| `opposed` | 双方对比，**比较方式可配**（成功等级 / 总值 / 差值） | COC / DND / 25 周年 |
| `free_opposed` | N 人排序 | 25 周年 |
| `extended` | 累计成功次数，开放或固定终止 | 25 周年 |
| `arbitrary` | 固定目标 10 | 25 周年 |
| `passive` | 不投骰，`10 + 修正`（优势 +5，劣势 −5） | DND |

### 6.3 修正器（Modifier）

仅 **COC 7e** 与 **DND 5e** 需要。妄想症两版**不注册任何修正器**（见 §9）。

```yaml
# COC 7e：奖励骰 / 惩罚骰
modifiers:
  - id: bonus_die
    kind: extra_dice
    source: gm
    visible: true
  - id: penalty_die
    kind: extra_dice
    source: gm
    visible: true
```

```yaml
# DND 5e：优势 / 劣势
modifiers:
  - id: advantage
    kind: keep_high
    dice: "2d20"
    visible: true
  - id: disadvantage
    kind: keep_low
    dice: "2d20"
    visible: true
```

修正器支持 `visible` 开关，但只有 COC / DND 会用到；妄想症完全不走这条路径。

## 7. 揭示等级（Reveal）

| 等级 | bot 输出 | 适用 |
|---|---|---|
| `full` | `d100 = 47 / 目标 60 → 成功（困难成功）` | COC 7e、DND 5e |
| `roll-only` | `d20 = 11` | **妄想症 2E / 25 周年（固定）** |
| `hidden` | 仅 `已记录` | 预留，暂无规则包使用 |

**为什么必须有这一层**：妄想症 2E 允许 GM 秘密调整目标值，25 周年允许其他玩家秘密花费搞事点数。若 bot 公开播报"目标值 + 成败"，会直接摧毁游戏的猜疑机制。

这同时也是安全设计上的收益：`roll-only` 模式下 bot 不持有权威结论，无法被当作"作弊裁判"来攻击，也不需要保存任何隐藏状态。

**注意：`roll-only` 不是"少显示一点"，而是"引擎不参与判定"。** 妄想症的规则包不注册目标值、不注册修正器、不算差值、不排序——只掷骰。

## 8. 对引擎的要求汇总

| # | 要求 | 来源 |
|---|---|---|
| 1 | 骰型可配置（d20 / d100） | 四套规则 |
| 2 | **方向可配**（`lte` 掷低 / `gte` 掷高） | DND 5e 是掷高，其余掷低 |
| 3 | 目标值来源可插拔（技能 / 属性 / 专精 / DC / 查表） | COC / DND |
| 4 | 加值链（属性调整 + 熟练） | DND 5e |
| 5 | 结果分级用**有序规则列表**，不用固定枚举 | COC 6 级 vs 其余 2 级 |
| 6 | 自然 1 / 20 规则**逐规则配置**，不能全局硬编码 | 妄想症 1/20，COC 百分比阈值，DND 无 |
| 7 | 对抗比较方式可配（成功等级 / 总值 / 差值） | COC / DND / 妄想症 |
| 8 | 多形态检定（normal / opposed / free_opposed / extended / arbitrary / passive） | DND / 妄想症 |
| 9 | 修正器（优势劣势 / 奖励惩罚骰 / GM 调整） | COC / DND |
| 10 | `reveal` 开关 | 妄想症 |
| 11 | 属性生成规则（如 `max(1d20, 8)`） | 25 周年角色卡 |
| 12 | **裸骰模式**：不取目标、不算修正、不判定 | 妄想症两版 |

**第 2 条与第 6 条是这次补完 DND 后新增的**——它们之前被"d20 掷低"的假象掩盖了。

## 9. 妄想症的简化结论

**判定权归 KP，引擎只掷骰。**

```
@bot /check 侦察
🎲 侦察  d20 = 11
```

| 项 | 实现 |
|---|---|
| 骰型 | 固定 `1d20` |
| 目标值 | 不读取、不显示 |
| 修正器 | 不注册（搞事点数、GM 调整都由 KP 心算） |
| 成败判定 | 不做 |
| 差值 | 不算 |
| 对抗 | 不排序，只并列列出各方骰值 |
| 长期检定 | 只掷 N 次并列出，不统计成功数 |

`/check <技能名>` 与裸 `/roll 1d20` 的唯一区别是**记录技能名**，用于审计与复盘（"这骰是为哪次检定掷的"）。

### 为什么这个简化是对的

| 收益 | 说明 |
|---|---|
| 消除私密输入需求 | 纯群聊没有单聊通道，KP 无法私密给 bot 传目标值。不判就不需要 |
| 消除隐藏状态 | bot 不持有"真实目标值"，不存在被查询泄漏的可能 |
| 消除信息泄露 | 公开播报会破坏妄想症的猜疑机制 |
| 减少规则包工作量 | 两个妄想症规则包共用同一个裸骰实现，只换角色卡 schema |

### 顺带解决的问题

之前记录的"搞事点数秘密花费无法在纯群聊实现"这一限制，随本决策**不再成立**——因为引擎根本不参与搞事点数的计算。

## 10. 与"确定性优先"的一致性

以上全部是**纯计算**，不含 LLM 调用，完全落在声明式 DSL 的表达范围内。

值得一提的是：由于妄想症走裸骰模式、COC / DND 走完全公开的判定，**引擎在任何规则包下都不需要保存"不可查询的隐藏状态"**。这消掉了此前担心的那类问题——不需要 KP 私密通道，也不需要为隐藏状态设计访问控制。

第 6 条（自然 1/20 逐规则配置）是本文件里最容易实现错的一条，建议用四个规则包各写一组单元测试锁死。
